# Handoff: Emerging Clarity — Website

## Production architecture

The production site is now generated by Astro from `src/` and deployed from `dist/` by `.github/workflows/pages.yml`.

- Edit canonical pages in `src/pages/`.
- Edit the shared document shell in `src/layouts/BaseLayout.astro`.
- Edit shared navigation and footer markup in `src/components/`.
- Edit shared behavior and design tokens in `public/site.js` and `public/site.css`.
- Keep static images and deployment controls under `public/`.
- Run `npm install` once, then `npm run build` before publishing.
- The root-level HTML/CSS/JS files remain temporarily as a rollback-safe copy during the GitHub Pages workflow cutover. Do not edit them as the production source.

Astro emits static HTML only. The migration preserves the approved markup, design, interactions, clean routes, and compatibility redirects.

## Overview
**Emerging Clarity** is the transformational-coaching site for Roberto Chavarria (one of three sibling brands under the personal brand *Roberto Chavarria*). It is a contemplative, intentionally **dark** marketing site whose job is to: book exploration calls, build an audience over time, look premium/credible, and make Roberto's philosophy *visible*.

The site is a small multi-page static site: **Home, About, The Work, The Essence, Connect, Stories**. A shared script injects the header/nav and footer into every page; a shared stylesheet holds all design tokens and components.

> **Brand intent — do not undo:** the dark mode is *meaningful* (crossing a threshold into inner, depth work). Keep it dark. Keep the teal accent, the heavy grotesque display type, the serif-italic accent phrase, the mono "label layer," the pill buttons, and the unhurried, soulful tone.

## About the Design Files
The files in this bundle are **design references built in plain HTML/CSS/JS** — working prototypes that show the intended look, content, and behavior. They are **not** meant to be shipped as-is. The task is to **recreate these designs in the target codebase's environment** using its established patterns (e.g. React/Next, Astro, Vue, etc.). If there is no existing environment, **Astro or Next.js** is a good fit for a content/marketing site like this.

Because every page already shares one CSS file and one JS file, this maps very cleanly onto a component model:
- `site.js`'s injected **nav** → a `<Header/>` component
- `site.js`'s injected **footer** → a `<Footer/>` component
- repeated section patterns (eyebrow chip, card, pill button, newsletter block, CTA band) → small reusable components
- each `.html` page → a route/page composed of those components

Teal-on-light rule: if any light surface is introduced, switch teal text/icons to `--aqua-deep` for contrast. (Currently the only light surface is the booking-calendar card on Connect, which uses blue `#1f8fcf`, not teal.)

### Typography
Three families (all Google Fonts):
- **Display / body:** `"Hanken Grotesk"` (weights 400–800). Headings are weight **800**, `letter-spacing: -0.03em`, `line-height: ~1.04`.
- **Label layer (mono):** `"IBM Plex Mono"` (400–600) — nav, eyebrow chips, captions, small labels. Uppercase, letter-spacing `~0.13–0.16em`.
- **Accent phrase (serif italic):** `"Newsreader"` *italic* — exactly one phrase per primary headline, colored teal. **Family rule:** one Newsreader-italic teal phrase per headline, no more.

Font CSS vars: `--font` (Hanken), `--font-mono` (IBM Plex Mono), `--font-serif` (Newsreader). Loaded via `@import` at the top of `site.css` plus a `<link>` per page for Hanken.

Fluid heading sizes use `clamp()`: hero `clamp(48px,7.4vw,104px)`, section titles `clamp(34px,4.6vw,60px)`, page-hero H1 `clamp(44px,7vw,96px)`. Base body `18px`/`line-height 1.6` (drops to `17px` ≤600px).

### Spacing / geometry
- Content widths: `--maxw: 1200px`, `--maxw-wide: 1340px`. `.wrap` adds `0 32px` gutters (`0 22px` ≤600px).
- Section vertical rhythm: `padding: clamp(88px,11vw,150px) 0`.
- Radii: `--radius: 16px`, `--radius-lg: 22px`; pills/chips use `border-radius: 999px`.
- Standard easing: `--ease: cubic-bezier(.22,.61,.36,1)`.

### Shadows
Soft teal-tinted glows on hover, e.g. card hover `0 30px 70px -40px rgba(132,194,198,.45)`; primary button hover `0 18px 40px -14px rgba(132,194,198,.6)`. No hard drop shadows.

- **Card** (`.card`): `--card` bg, `1px --line` border, `--radius-lg`, `32px` padding; hover lifts `-6px`, border tints teal, bg → `--card-2`, teal glow.

- **Secondary button** (`.btn.btn--ghost`): transparent pill, `1.5px --line` border; hover → teal border + text.
- **Text link** (`.tlink`): inline label with trailing arrow; gap widens and color → bright teal on hover.
- **Newsletter block** (`.news`): bordered rounded panel with a faint teal corner-glow; email input (pill) + primary button; on submit, JS adds `.sent` to reveal a teal confirmation line (`.ok`). **Mock only — wire to a real provider.**

- **Scroll reveal** (`.reveal`, optional `data-d="1..5"` stagger): elements start `opacity:0; translateY(28px)` and transition to visible when an `IntersectionObserver` adds `.in`. Honors `prefers-reduced-motion` (everything shown immediately).

## Interactions & Behavior
- **Nav:** scroll past 40px → `.scrolled` chrome; active page link highlighted (in production, derive from the current route). ≤940px burger toggles the menu; clicking a link closes it.
- **Scroll reveal:** `IntersectionObserver` (threshold 0.12, `rootMargin 0px 0px -7% 0px`) adds `.in` once per element; `data-d="1..5"` adds 0.08s-stepped delays. **Honor `prefers-reduced-motion`** (show everything, no transforms).
- **Buttons/links:** hover lifts + teal glow; arrow icons nudge; text-links widen their gap.
- **Newsletter forms:** `submit` is intercepted, adds `.sent` to show a thank-you, resets the field. **Mock — connect to a real ESP (e.g. ConvertKit/Mailchimp) endpoint.**
- **Calendar (Connect):** client-side mock for June 2026; clicking an available day selects it. **Replace with the real Calendly embed.**
- **Smooth scroll** for in-page `#anchors`.

## State Management
Minimal — this is a marketing site. State needed: nav scrolled (boolean), mobile menu open (boolean), per-element reveal-seen (handled by observer), newsletter "sent" (boolean), calendar selected-day. In a component framework, header/footer become components; reveal becomes a small hook/directive or a CSS scroll-driven animation; forms post to a real endpoint.
